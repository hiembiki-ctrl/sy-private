# 일정 콘텐츠 출처

## Decisions

- 도시별 일정(명소와 액티비티)은 앱에 담긴 직접 작성한 정적 데이터에서 읽는다.
- 일정 데이터는 한 곳에서만 읽어서, 나중에 외부 API 출처로 교체해도 사용하는 쪽이 바뀌지 않게 한다.

## Boundaries

- 실시간 외부 장소 API, 생성형 모델 호출, 사용자별 저장 데이터는 이 결정이 다루지 않는다.

## Why

API 키와 외부 서비스 없이 한 번에 구현하고 실제 클릭으로 검증할 수 있고, 일정 품질을 직접 통제해 낯선 여행지에 관심이 생기는지 바로 판단할 수 있다.

## Reconsider when

- 지원 도시를 직접 작성으로 감당할 수 없을 만큼 늘려야 할 때
- 일정 내용을 사용자 입력이나 실시간 정보에 맞춰야 할 때

## Still-rejected alternatives

- 클릭할 때마다 LLM이나 장소 API로 일정을 생성하는 방식 — 키, 비용, 지연, 결과 편차를 감당해야 하고 이번 범위에서 검증하기 어렵다. 도시 수나 최신성 요구가 커지면 다시 검토한다.

## Evidence worth preserving

- 후보 장소 API(2026-10 검색 기준): OpenTripMap(관광 전용, 무료 한도 미확인), Geoapify Places(무료 하루 3,000건), Foursquare Places(월 500건 무료 이후 유료, 가격 정책 최근 변경). 어느 것도 일정을 짜 주지 않고 장소 목록만 주므로, 하루 단위로 묶는 로직이 별도로 필요하다. 사용 전 공식 페이지에서 한도와 약관을 다시 확인한다.
