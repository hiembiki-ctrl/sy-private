# 일정 콘텐츠 출처

## Decisions

- 도시와 명소·액티비티는 Supabase Postgres의 여행지 카탈로그(`cities`, `city_places`)에서 읽는다. 누구나 읽을 수 있다.
- 카탈로그를 읽는 곳은 `lib/catalog.ts`의 `loadCities` 하나다. 사용하는 쪽은 출처를 모른다.
- DB 설정이 없거나 읽기에 실패하거나 비어 있으면 앱에 담긴 정적 데이터(`lib/cities.ts`, `lib/nearby-trips.ts`)로 대신한다. 도시 열람은 DB 연결 여부에 의존하지 않는다.
- 저장 일정의 `city_id`는 `cities`를 가리키는 외래 키다. 도시를 추가해도 저장 일정 테이블은 고치지 않는다.
- 카탈로그에 쓰는 경로는 둘이다. 직접 작성한 콘텐츠를 대시보드나 SQL로 넣는 경로와, 로그인한 사용자의 요청으로 위키 공개 데이터(한국어 위키백과, 위키데이터, 위키보이지)를 모아 넣는 경로다. 요청 경로로 들어온 장소는 출처 문서 주소를 함께 저장하고 화면에 보여 준다.
- 외부에서 가져와 DB에 저장하고 공개하는 내용은 저장과 재공개가 허용되는 출처로만 한정한다. Google의 검색 근거(grounding)와 Places 내용은 이 용도로 쓰지 않는다.

## Boundaries

- 요청 경로의 쓰기는 서버만 한다. 일반 사용자 권한으로는 카탈로그에 쓸 수 없다.
- 생성형 모델이 장소를 지어내는 방식과, 클릭할 때마다 외부 API를 호출해 일정을 만드는 방식은 이 결정이 다루지 않는다.

## Why

실제 여행지 정보를 많이 확보하려면 코드 수정과 재배포 없이 데이터를 늘릴 수 있어야 하고, 사용자 요청으로 늘리려면 한 번 가져온 내용을 저장해 다음부터 DB에서 읽어야 한다. 이미 계정과 저장 일정에 Supabase를 쓰므로 같은 DB가 가장 단순하다. SQLite 파일은 서버리스 배포에서 읽기 전용이고 네이티브 모듈이 필요해 채택하지 않았다. 저장을 허용하는 출처를 고른 것은 약관 때문이다. 위키백과 글은 출처를 밝히면 저장과 재공개가 허용된다.

## Reconsider when

- 장소 수가 수만 건을 넘어 도시별 전체 조회가 느려질 때
- 위키 공개 데이터로는 소도시의 근교와 좌표를 채우기 어려워 품질이 목표에 못 미칠 때
- Google이 검색 결과의 저장과 재공개를 허용하도록 약관을 바꿀 때

## Still-rejected alternatives

- Google Gemini의 Google 검색 근거(grounding) — 약관이 결과로 색인이나 DB를 만드는 것을 금지하고, 결과를 요청한 사용자에게만 보여 주고 검색 제안 문구를 함께 표시하라고 한다. 저장해 공유하는 이 기능과 맞지 않는다.
- Google Places API (New) — 장소 ID만 무기한 저장할 수 있고 이름과 요약 같은 내용의 캐시와 저장은 Maps 약관이 제한한다. 매번 호출하는 구조는 열람이 DB 중심이라는 원칙과 로그인 없이 가볍게 둘러본다는 원칙을 크게 바꾼다.
- Google Custom Search JSON API — 신규 고객에게 닫혀 있고 기존 고객도 2027-01-01에 종료된다.
- SQLite 파일 — 위 Why 참고.

## Evidence worth preserving

- 약관 확인(2026-10): Gemini API 약관은 grounding 결과를 캐시하거나 분석하거나 색인·DB를 만드는 데 쓰는 것을 금지한다. Places API 정책은 장소 ID 외의 내용을 사전 수집·캐시·저장하는 것을 금지하며 예외는 Maps Platform 서비스 약관에 있다. 구현 전에 공식 약관을 다시 확인한다.
- 위키 공개 API 수집 실험(2026-10, 이 프로젝트): 한국어 위키백과는 좌표가 붙은 문서가 적어서 영어판 좌표 검색으로 후보를 찾고 한국어판 문서가 있는 것만 쓰는 방식이 필요했다. 한 도시와 근교 4곳을 모으는 데 약 1~2분이 걸렸고, 작은 도시의 근교는 후보가 0~1건인 경우가 흔했다. 위키백과 글은 CC BY-SA 4.0이라 출처 표시가 필요하다.
- 후보 장소 API(2026-10 검색 기준): OpenTripMap(관광 전용, 무료 한도 미확인), Geoapify Places(무료 하루 3,000건), Foursquare Places(월 500건 무료 이후 유료, 가격 정책 최근 변경). 어느 것도 일정을 짜 주지 않고 장소 목록만 주므로 하루 단위로 묶는 로직이 별도로 필요하다. 사용 전 공식 페이지에서 한도와 약관을 다시 확인한다.
