# 로그인하고 일정 저장하기

## 사용자 결과

여행지를 둘러보다 마음에 든 도시와 일수를 이메일 계정으로 로그인해 저장해 두고, 나중에 다시 와서 저장한 목록에서 바로 열어 볼 수 있다. 로그인하지 않아도 지구본, 도시, 일정 열람은 지금과 똑같이 쓸 수 있다. 이 작업은 저장 일정을 사용자별로 보관하는 기반을 만들고, 저장 일정을 이용한 맞춤 정보는 다음 작업이다.

## 범위

### 포함

- 화면 오른쪽 상단에 "로그인" 진입점이 있다. 로그인하면 계정 표시(이메일)와 로그아웃이 보인다.
- 로그인은 이메일과 비밀번호 하나만 지원한다. 처음 쓰는 사용자는 같은 입력 화면에서 가입할 수 있다. 로그인 뒤에는 처음 화면으로 돌아오고, 새로고침해도 로그인 상태가 유지된다.
- 로그인하지 않은 사용자도 지구본, 도시 선택, 일수 변경, 일정 열람을 전과 똑같이 쓴다. 저장 관련 기능만 로그인이 필요하다.
- 도시를 선택하면 일정 영역에 저장 동작이 보인다.
  - 로그인한 사용자: 현재 도시와 일수를 "저장"할 수 있다. 이미 저장한 조합이면 "저장됨"으로 보이고 다시 눌러 저장을 해제할 수 있다.
  - 로그인하지 않은 사용자: 같은 자리에 "로그인하고 저장"이 보이고, 누르면 이메일 로그인 입력이 열린다.
- 로그인한 사용자에게는 "내 저장 일정" 목록이 보인다. 항목은 도시 이름과 일수(예: 파리 3일)이고, 항목을 누르면 그 도시가 선택되고 그 일수로 일정이 열린다. 항목마다 삭제할 수 있다.
- 저장 일정은 사용자별로 보관된다. 같은 사용자가 같은 도시와 일수 조합을 중복 저장할 수 없고, 같은 도시의 다른 일수는 따로 저장할 수 있다.
- 한 사용자의 저장 일정은 다른 사용자와 로그인하지 않은 사람이 읽거나 바꿀 수 없다.

### 제외 (다음 작업으로 미룸)

- 저장 일정을 이용한 맞춤 정보와 추천
- 여행 날짜, 메모, 일정 항목 수정, 목록 정렬과 공유
- Google 같은 외부 계정 로그인, 비밀번호 재설정, 계정 삭제
- 프로필 정보 편집과 설정 페이지
- 로그인 전에 보던 도시와 일수를 로그인 뒤에 되살리는 것
- 예약, 결제

## 수용 기준

1. 로그인하지 않은 상태에서 지구본, 도시 선택, 일수 변경, 일정 열람이 기존과 똑같이 동작하고, 로그인을 요구하는 화면이나 안내 가림막이 나타나지 않는다.
2. 로그인하지 않은 상태에서 도시를 선택하면 일정 영역에 "로그인하고 저장"이 보이고, "내 저장 일정" 목록은 보이지 않는다.
3. "로그인하고 저장"이나 로그인 진입점을 누르면 이메일과 비밀번호 입력이 열린다. 가입하거나 로그인하면 앱의 처음 화면으로 돌아오고 계정 표시가 보인다.
4. 로그인한 상태에서 새로고침해도 로그인 상태가 유지된다. 로그아웃하면 계정 표시와 "내 저장 일정"이 사라지고 로그인 진입점이 다시 보인다.
5. 로그인한 상태에서 도시를 선택하고 "저장"을 누르면 즉시 "저장됨"으로 바뀌고, "내 저장 일정"에 "도시명 N일" 항목이 나타난다.
6. 같은 도시를 다른 일수로 바꾸면 저장 동작이 다시 "저장"으로 보이고, 저장하면 목록에 별개 항목이 추가된다. 같은 조합을 다시 저장하려는 동작은 항목을 늘리지 않는다.
7. 새로고침하거나 로그아웃 후 다시 로그인해도 저장 일정이 그대로 남아 있다.
8. "내 저장 일정"의 항목을 누르면 해당 도시가 선택되고 지구본이 그 도시로 돌아가며 저장된 일수의 일정이 열린다.
9. 저장을 해제하거나 목록에서 삭제하면 항목이 사라지고, 새로고침해도 돌아오지 않는다.
10. 서로 다른 두 계정으로 각각 저장한 뒤, 한 계정에서는 다른 계정의 저장 일정이 목록에 보이지 않고 다른 계정의 항목을 읽거나 삭제할 수 없다. 로그인하지 않은 상태에서도 저장 일정을 읽거나 쓸 수 없다.
11. 저장소나 로그인 서비스에 연결할 수 없는 상태에서도 수용 기준 1의 열람 기능은 정상 동작하고, 저장이나 로그인을 시도하면 실패를 알리는 메시지가 보인다.
12. 좁은 화면(약 390px)에서도 로그인 진입점, 저장 동작, "내 저장 일정"이 가려지지 않고 가로 스크롤이 생기지 않는다.
13. 저장되는 정보는 도시와 일수, 저장 시각뿐이다. 지원하지 않는 도시나 1~3일 밖의 일수는 저장되지 않는다.

## 확정한 결정과 근거

- 계정과 저장은 Supabase(이메일 로그인 + Postgres)로 하고, 열람은 계정과 분리한다. [account-and-storage](../../decisions/account-and-storage.md)가 서비스 선택과 소유자 전용 접근 원칙을 다룬다.
- 저장하는 대상은 도시와 일수 한 쌍이다. 사용자가 확정했다. 용어는 [GLOSSARY.md](../../../GLOSSARY.md)의 저장 일정을 따른다.
- 일정 콘텐츠는 계속 앱에 담긴 정적 데이터에서 읽는다. [itinerary-content-source](../../decisions/itinerary-content-source.md)를 바꾸지 않는다. 저장소에는 일정 내용이 아니라 도시와 일수만 들어간다.
- 지구본과 도시 선택 동작은 [map-surface](../../decisions/map-surface.md)와 기존 스펙 [city-itinerary-explorer](../city-itinerary-explorer/spec.md)를 그대로 따른다.
- 일반 UI(로그인 버튼, 저장 버튼, 목록, 오류 표시)는 [ui-composition](../../decisions/ui-composition.md)을 따른다.
- 앱 전체 전제는 [PRODUCT.md](../../../PRODUCT.md)를 따른다. 이 작업에 해당하는 제약은 가볍고 단순한 경험, 서비스 안에서는 개요 수준만 보여주는 것이다. PRODUCT.md에는 로그인 없는 열람, 이메일 로그인, 도시와 일수 저장이 이미 반영되어 있다.

## 가정 (덮어쓸 수 있음)

- 저장 동작은 일정 영역의 도시 정보 가까이에 둔다. 목록은 도시 목록 아래나 일정 위에 둔다.
- 로그인하면 계정 이름이 있으면 이름을, 없으면 이메일을 표시한다.
- 저장 일정 목록의 순서는 최근에 저장한 것이 위다.
- 목록 개수 제한은 두지 않는다.
- 별도의 프로필 정보 저장은 하지 않는다. 계정 식별은 로그인 서비스가 관리하는 것으로 충분하다.
- 로그인 전에 보던 도시와 일수는 로그인 뒤에 되살리지 않는다. 로그인 뒤에는 처음 화면에서 시작한다.
- 로그인과 저장소에 쓰는 키 중 클라이언트에 두는 것은 공개 가능한 키뿐이고 비밀값은 저장소에 넣지 않는다.

## 사용자가 직접 해야 하는 준비 (구현 전 필요)

- Supabase 프로젝트를 만들거나 기존 프로젝트를 정한다.
- Supabase 대시보드에서 이메일 로그인의 "이메일 확인" 설정을 켤지 끌지 정한다. 학습과 개발 중에는 끄는 것을 권장한다. 켜 두면 가입 확인 메일이 필요하고, 확인 링크가 돌아올 주소(예: http://localhost:3000)를 허용 목록에 등록해야 한다.

위 두 가지가 정해지지 않으면 구현은 가입과 로그인의 실제 동작 검증에서 멈춘다.

## 건드리지 않는 것

- 지구본, 도시 일정 콘텐츠, 일수 선택의 기존 동작. 로그인과 저장이 이를 바꾸거나 느리게 하지 않는다.
- 계정이 필요 없는 기능을 로그인 뒤로 옮기는 것. 열람은 계속 열려 있어야 한다는 사용자 요구다.

## 미룬 결정

- 저장 일정을 이용한 맞춤 정보가 무엇이고 어떻게 보이는지. 다음 사용자 결과로 따로 정한다.
- 로그인 전 선택 상태를 로그인 뒤에 되살릴지. 현재는 되살리지 않는 것이 임시 동작이다.
- 저장 일정 정렬, 공유, 날짜와 메모 추가.
- Google 등 외부 계정 로그인.
- 예약, 결제, 일정 항목 수정을 제품 경계에 넣을지. (PRODUCT.md의 미정 항목)

## 남은 위험

- 이메일 확인을 켜 두면 Supabase 기본 메일 서비스의 발송 제한으로 가입 확인 메일이 막히거나 늦을 수 있다. 이 경우 가입 직후 로그인 검증이 지연된다.
- Supabase 무료 플랜은 7일 동안 사용이 없으면 프로젝트가 일시정지된다. 그 동안 로그인과 저장이 실패하지만 열람은 영향을 받지 않아야 한다(수용 기준 11).
- `@supabase/ssr`가 이 프로젝트의 Next.js 16과 React 19에서 동작하는지 아직 확인하지 못했다. 안 되면 연동 방식을 다시 정한다.
- 로그인 리다이렉트 허용 주소가 실제 로컬·배포 주소와 맞지 않으면 로그인이 중간에 실패한다.
- 로그인 뒤 처음 화면으로 돌아오면 선택하던 도시가 사라진다. 사용자가 불편해하면 선택 복원을 다음 작업으로 올린다.
